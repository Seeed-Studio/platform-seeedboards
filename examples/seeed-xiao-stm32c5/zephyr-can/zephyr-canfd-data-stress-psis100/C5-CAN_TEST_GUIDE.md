# XIAO STM32C5 CAN FD Throughput Test Guide

This guide defines repeatable transmit, receive, bidirectional, and multi-node
tests for the CAN FD data-phase stress sample.

## Host adapter configuration

Configure every node with the same nominal bit rate, data bit rate, frame
format, and compatible sample points. The examples use 1 Mbit/s nominal,
8 Mbit/s data, CAN FD with BRS, and one 120-ohm termination resistor at each
physical end of the bus. Verify lower rates before increasing the data rate.

## Commands

```text
cfd start <tx|rx|bidi|loop> [nominal] [data] [bytes] [seconds] [fps] [can|fd|fd-brs] [pattern]
cfd stop
cfd status
cfd id [000..7ff]
cfd clock
cfd regs
```

Patterns are `fixed`, `fixed-8`, `fixed-64`, `alt-8-64`, and `mix-canfd`.
An `fps` value of `0` removes application-level rate limiting.

## Transmit tests

```text
cfd start tx 1000000 8000000 64 30 0 fd-brs fixed-64
cfd start tx 1000000 8000000 8 30 0 fd-brs fixed-8
cfd start tx 1000000 8000000 64 30 0 fd-brs alt-8-64
cfd start tx 1000000 8000000 64 30 0 fd-brs mix-canfd
```

Use a finite rate when the host adapter cannot process unlimited traffic:

```text
cfd start tx 1000000 8000000 64 30 1000 fd-brs fixed-64
```

## Receive and bidirectional tests

Start the receiver before transmitting from the host adapter:

```text
cfd start rx 1000000 8000000 64 30 0 fd-brs
cfd start bidi 1000000 8000000 64 30 0 fd-brs fixed-64
cfd start bidi 1000000 8000000 64 30 1000 fd-brs fixed-64
```

Frames that follow the sample payload format contribute to `checked`; other
valid frames contribute to `unchecked`. During a bidirectional test, the host
must acknowledge XIAO traffic while transmitting with matching timing.

## Multi-node tests

Assign a different standard transmit identifier to each XIAO:

```text
XIAO A:
cfd id 504
cfd start tx 1000000 8000000 64 30 0 fd-brs fixed-64

XIAO B:
cfd id 505
cfd start tx 1000000 8000000 64 30 0 fd-brs fixed-64
```

Use a linear bus and do not terminate intermediate nodes.

## Result interpretation

```text
summary ... tx_ok=... tx_fail=... tx_cb_err=... rx=... checked=... gap=...
perf elapsed_ms=... tx_fps=... rx_fps=... tx_payload_bps=... rx_payload_bps=... total_payload_bps=...
quality tx_error_permille=... rx_loss_permille=... total_error_permille=...
estimate configured_nominal_bps=... configured_data_bps=... est_nominal_phase_bps=... est_data_phase_bps=...
```

- `tx_fail` reports immediate submission failures.
- `tx_cb_err` reports asynchronous completion errors.
- `gap` reports missing sequence numbers in checked receive traffic.
- `content_err` reports payload validation failures.
- Permille values are tenths of a percent; divide by 10 for a percentage.
- Length histograms confirm the distribution generated by mixed patterns.

A clean run keeps the controller error-active, reports zero transmit and
receive loss, content errors, and overruns, and does not show continuously
increasing ACK, bit, CRC, form, or stuff errors. Published results should state
the cable length, termination, transceiver, adapter, timing, duration, frame
pattern, and complete summary.
